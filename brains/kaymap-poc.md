# 键位映射方案（架构与原理）

面向 macOS 辅助工具：在**指定目标应用前台**时，用键盘单键触发窗口内相对坐标点击（或 Escape 类动作）；支持第三方键位方案导入，以及目标窗口上的 overlay 编辑。交互参考 PlayCover / 模拟器键鼠方案，技术路径与「系统全局热键库」不同。

## 问题拆分

| 问题 | 本质 |
|------|------|
| 录制 / 自定义键位 | 把「物理键」绑定到「窗口内动作」（点触坐标、返回键等） |
| 仅目标 App 生效 | 焦点门控：前台 bundle 与绑定目标一致才分发 |
| 兼容 PlayCover 等方案 | 厂商文件格式 → 统一领域模型；解析器可插拔 |
| Overlay 编辑 | 透明层贴齐目标窗口，拖拽改位置、按键改绑定 |

**不应采用**：系统快捷键 Recorder 类库（通常要求修饰键、注册 Carbon/全局热键、与「单键 → 屏幕点」模型不匹配）。

## 总体架构

按领域拆成独立模块（单向依赖，禁止反向）：

```text
应用壳（菜单栏 / 设置 / 组装）
    ├── 方案适配（PlayCover 等） ──► 键位核心
    ├── 编辑器（Overlay UI） ─────► 键位核心
    └── 输入运行时 ──► 键位核心
                   ├──► 注入层 ──► 窗口/坐标定位
                   └──► 窗口/坐标定位
```

| 领域 | 职责 |
|------|------|
| 键位核心 | 厂商无关的规范模型、解析器协议、注册表、本地持久化 |
| 方案适配 | 某一厂商文件 ↔ 规范模型（首期 PlayCover；预留 MuMu / 雷电） |
| 窗口定位 | 前台/指定进程的焦点窗口 frame、相对坐标 ↔ 屏幕坐标（AppKit / Quartz） |
| 注入 | 向目标 PID 投递鼠标点击或 Escape（多路径可降级） |
| 输入运行时 | 监听按键、焦点门控、查表触发注入；编辑模式旁路 |
| 编辑器 | 贴窗 overlay、渲染绑定点、拖拽与录键 |
| 应用壳 | 绑定目标、导入方案、进入编辑、选择注入路径、状态展示 |

## 规范模型（厂商无关）

编辑、运行、持久化**只认**规范键位图，不直接依赖某模拟器字段名。

**元素类型（可扩展）：**

- **Button**：单键 → 窗口内一点（点击）
- **DraggableButton**：数据上等同可拖按钮；运行时首期可与 Button 同样按「按下触发点击」处理
- **Joystick / MouseArea**：导入时保留，避免丢方案；首期运行时可不执行，编辑器可灰显

**单键绑定：**

- 内部键码统一为 **NSEvent / Carbon 虚拟键码** 语义（便于监听层匹配）
- 显示名（如 `K`、`Esc`）仅用于 UI
- 鼠标键（LMB 等）可用特殊码表示；若不做鼠标绑定运行时可忽略

**变换（相对窗口）：**

- 原点：窗口**左上**
- `x` / `y` / `size` 为相对窗口宽高的归一化量（约 0…1 或与厂商同语义的相对比例）
- 注入时：`屏幕点 = 当前窗口 frame × 相对坐标`（缩放/移动窗口后仍准）

**元数据：**

- 目标提示（bundle id / 包名）
- 来源（PlayCover 版本、Arkeys 自有、未知等）

持久化建议：按目标标识存一份规范模型的 JSON（Application Support）；导入时可另存原始 bytes 便于对照。

## 可插拔方案解析

### 协议能力

每个厂商适配器实现同一接口，至少包括：

1. **方案 ID / 显示名**（playCover、muMu、ldPlayer…）
2. **可识别的扩展名或 UTI**
3. **嗅探**：给定字节与文件名，判断是否为本方案
4. **解码**：字节 → 规范键位图
5. **编码**：规范键位图 → 字节（不支持则明确失败）

### 注册表

- 启动时注册已实现的适配器列表
- **导入**：嗅探 → 解码 → 写入规范存储并应用到当前目标
- **导出**：按用户选择的方案 ID 取适配器编码
- 未实现的厂商只占 ID 与占位，不假装能解析

### PlayCover（首期必须）

对齐公开键位结构（button / draggable / joystick / mouseArea、相对 transform、bundleIdentifier、version）：

| 厂商字段含义 | 规范模型 |
|--------------|----------|
| 普通按钮列表 | Button |
| 可拖按钮列表 | DraggableButton |
| 摇杆 / 鼠标区 | Joystick / MouseArea（入库，运行可暂不执行） |
| 相对位置与尺寸 | 归一化 transform |
| bundleIdentifier | 目标提示 |
| version | 来源元数据 |

要点：

- 文件多为 XML plist；扩展名常见 `.plist` / `.playmap`
- 厂商键码为 **GameController 风格整数**，与 NSEvent 键码**不是同一套**：适配器内做双向映射；规范层只暴露 NSEvent 语义
- 负键码表示鼠标键等特殊绑定
- 验收：真实或裁剪 fixture 能解码出正确按钮数、相对坐标、关键键；button 级 encode/decode 可 round-trip

### 后续厂商

- MuMu：多为私有 `.cfg`（keymap 配置目录）
- 雷电：独立格式，同样只经适配器进入规范模型
实现时只新增适配模块并注册，不改运行时与编辑器对规范模型的假设。

## 运行时原理

### 焦点门控

1. 用户绑定目标应用（bundle id；避免绑到本工具自身）
2. 每次按键：若前台应用 ≠ 目标 → **直接忽略**
3. 未启用或未绑定目标 → 忽略

### 单键优先

- 匹配时要求无 ⌘ / ⌥ / ⌃ / ⇧（可忽略 Caps Lock）
- 用虚拟键码在规范图的 Button（及约定的可运行按钮）中查找
- 命中 → 用该元素相对坐标解析当前窗口 → 调用注入层点击

### 编辑模式

- 进入编辑后：运行时**不注入**，把按键交给编辑器用于改绑定
- 退出编辑：写回规范模型并持久化

### 监听方式

- 全局 + 本地按键监听（需 Accessibility；非沙盒更稳妥）
- 与「注册系统热键」解耦：可占用单键，且仅在目标前台消费业务逻辑

注入路径（点击 / Escape）沿用分层策略（如 per-PID、SkyLight、HID 降级），细节见注入可行性调研；键位层只负责「何时、点哪里」。

## Overlay 编辑原理

交互对齐模拟器键位编辑（非进程内注入 UI）：

1. **贴窗**：无边框浮动窗，frame 跟随目标焦点窗口（定时或观察移动/缩放）
2. **编辑时可点**：接收鼠标；非编辑时隐藏或忽略鼠标
3. **空白处点击**：在归一化坐标处新增 Button（待绑定）
4. **拖拽**：更新该元素相对 `x/y`
5. **选中后按键**：写入键码与显示名
6. **删除**：移除选中元素
7. **完成 / 取消**：提交或丢弃对规范模型的修改

Joystick / MouseArea：可显示为只读标记，避免用户误以为已支持运行时。

编辑器**不依赖**任何厂商 DTO，只读写规范模型；导入导出一律走注册表。

## 应用壳职责

- 绑定目标应用：从运行列表选择（半透明浮层预览窗口）或「绑定前台」
- 新建空白键鼠方案、导入方案（首期 PlayCover）、清空键位、进入 overlay 编辑
- 启用开关、注入路径选择、能力探测与最近一次注入日志
- 组装：注册 PlayCover 解析器；后续追加厂商解析器即可

## 首期范围

**做：**

- 规范模型 + 解析器协议 + 注册表
- PlayCover 导入/导出（button 级 round-trip）
- Overlay 编辑 Button
- 目标前台单键 → 相对坐标点击

**不做（可后续加）：**

- MuMu / 雷电真实解析
- Joystick / MouseArea 运行时注入
- 系统热键库、进程内触屏 hook（PlayTools 那套）

## 实现者提示

- 先定规范模型与解析器协议，再写适配器与 UI，避免 UI 绑死厂商字段
- 键码转换表集中在适配器；运行时只比 NSEvent 键码
- 坐标全程用相对比例，注入瞬间再乘当前 window frame
- 领域分包、依赖单向；应用壳只做组装与权限/菜单
